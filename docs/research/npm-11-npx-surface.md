# npm 11 / npx user-facing surface — reference for a drop-in replacement (as of 2026-10-04)

## 0. Version landscape (read first — it changes how to read the docs)

- **`latest` on the registry is npm 12.2.0 (2026-09-30)**; npm 12.0.0 went GA 2026-07-08. The npm 11 line continues as `next-11` = **11.21.0** (GitHub's newest v11 tag is `v11.20.0`). Source: `GET https://registry.npmjs.org/-/package/npm/dist-tags`, https://github.com/npm/cli/blob/latest/CHANGELOG.md, https://github.blog/changelog/2026-07-08-npm-install-time-security-and-gat-bypass2fa-deprecation/
- docs.npmjs.com/cli/v11 is now labelled "Legacy"; the version each page renders trails the `next-11` tag and varies by page, so treat the CHANGELOG as the authority for what a given 11.x release contains. **Caveat:** several v11 pages were regenerated from v12 text: `npm-install-scripts` says dependency scripts are "blocked by default", while `npm-approve-scripts`/`npm-deny-scripts` (same site, same version) say "install scripts still run by default… a future release will block". The latter is the real npm 11 behaviour (advisory warnings since 11.16.0; blocking is npm 12). Likewise the `npm-audit` page still describes a "Quick Audit" fallback that 11.0.0 removed.
- Node.js Release WG decided **not** to ship npm 12 in Node 22/24/26 (https://github.com/nodejs/Release/issues/1161), so npm 11 remains what most Node installs carry; Node 27 is the first to bundle npm 12.
- Engines: npm 11 requires node `^20.17.0 || >=22.9.0`; npm 12 requires `^22.22.2 || ^24.15.0 || >=26.0.0`.

### npm 11.0.0 breaking changes vs npm 10 (2024-12-16; https://github.com/npm/cli/releases/tag/v11.0.0)
- `npm publish` fetches all prior versions and refuses to implicitly tag `latest` if the version is lower than the current highest non-prerelease version; **pre-release versions require an explicit `--tag`**.
- `--ignore-scripts` now applies to *all* lifecycle scripts incl. `prepare`; `npm pack --ignore-scripts` added.
- Audit no longer falls back to the old "quick audit" endpoint when the bulk advisory request fails.
- `npm hook` command removed. No more implicit global mode when aliased `npmg`/`npm-g`.
- `npm init` gained a `type` prompt / `--init-type` (11.2) and sorts generated package.json differently; `bun.lockb` always excluded from tarballs.
- Attestations made by npm ≥11 don't validate on npm <10.6.0.

### Notable additions during 11.x (CHANGELOG)
11.1 `npm undeprecate`, `--dry-run` for (un)deprecate · 11.2 `npm cache npx ls|rm|info`, `--init-type`, warn on unknown `.npmrc` keys · 11.3 `node-gyp` config · 11.4 `npm run` is the canonical name (`run-script` alias), `--init-private`, `npm install --json` package info · **11.5.0/11.5.1 OIDC trusted publishing** · 11.6 `${VAR?}` optional env substitution in `.npmrc` · 11.7 (Dec 2025) `npm token create` makes **granular** tokens (classic removed) · 11.8 proxy env shown in `config list` · 11.9 `--allow-git` · 11.10 `npm trust`, `min-release-age` · 11.11 CircleCI for trust/OIDC, `:type(registry)` selector · 11.12 `npm audit signatures --include-attestations` · 11.15 `--allow-remote/--allow-file/--allow-directory` (trust commands require ≥11.15.0 server-side) · **11.16 Phase-1 `allowScripts` policy** (`npm approve-scripts`, `npm deny-scripts`, `allow-scripts`, `strict-allow-scripts`, `dangerously-allow-all-scripts`, advisory warnings) · 11.17–11.19 `npm stage` (staged publishing), `npm install-scripts approve|deny|ls|prune`, `npm trust --allow-publish/--allow-stage-publish`.

### npm 12.0.0 breaking changes (for "where is this going"; https://github.com/npm/cli/blob/latest/CHANGELOG.md)
Dependency install scripts blocked unless allowed by root `allowScripts`; `allow-git` and `allow-remote` default `none`; root `preinstall` now runs *before* deps install; unknown CLI flags/abbreviations throw (unknown `.npmrc` keys warn; `strict-npmrc` to error); `npm shrinkwrap` + `npm-shrinkwrap.json` support removed; `npm adduser`, `star`/`stars`/`unstar` removed; `npm view --json` always an array; `npm pkg` output no longer forced JSON; `pack`/`publish` `--json` unified; no man-page registration on global install; `npm init` default license empty; `npm patch` (dependency patching), `packageExtensions`, `min-release-age-exclude`, `u` alias for update, global `.npmignore`, `--access=private` alias, `linked` install strategy stable.

## 2. `npm install` semantics (https://docs.npmjs.com/cli/v11/commands/npm-install, https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json, https://docs.npmjs.com/cli/v11/configuring-npm/package-json, https://docs.npmjs.com/cli/v11/configuring-npm/folders)

**Lockfile precedence**: `npm-shrinkwrap.json` > `package-lock.json` > `yarn.lock` (yarn.lock only mined for resolved/integrity hints; `checkYarnLock` in arborist/shrinkwrap.js). Lock vs package.json: if lock satisfies ranges, lock wins; otherwise package.json wins and lock is rewritten. `npm ci` errors on mismatch and never writes. Project root found by walking up for `package.json` or `node_modules`.

**package-lock.json v3** (`lockfileVersion: 3`, default for new locks; v1 auto-converted to v3; `--lockfile-version 1|2|3`): `name`, `version`, `lockfileVersion`, `packages` map keyed by path relative to root (`""` = root, `node_modules/foo`, `node_modules/foo/node_modules/bar`, `packages/a` for workspaces) with fields `version`, `resolved` (tarball URL; git URL with commit sha; link target path; `registry.npmjs.org` host is a magic "configured registry" value, see `replace-registry-host`), `integrity` (sha512 SRI, sha1 for old publishes), `link: true` (no other fields), `dev`/`optional`/`devOptional`, `peer`, `inBundle`, `hasInstallScript`, `hasShrinkwrap`, `bin`, `license`, `engines`, `dependencies`, `optionalDependencies`, `peerDependencies`, `peerDependenciesMeta`, `os`, `cpu`, `libc`, `funding`, `deprecated`, `workspaces` (root). v2 adds the legacy `dependencies` tree for npm 6. Indentation/line endings inferred from package.json; `format-package-lock` config; `omit-lockfile-registry-resolved` drops `resolved` for registry deps. **Hidden lockfile** `node_modules/.package-lock.json` (always v3) is used instead of reading node_modules when: every listed folder exists, no unlisted folders exist, and its mtime ≥ every package folder's mtime; otherwise ignored.

**Hoisting (Arborist)**: build-ideal-tree places each dep as shallowly as possible without conflicting (`place-dep.js`); duplicates nest under the dependent; newer versions preferred over dedupe unless `--prefer-dedupe`; deterministic but order-sensitive. `--install-strategy=hoisted|nested|shallow|linked` (`nested` = old `--legacy-bundling`, `shallow` = old `--global-style`, `linked` = `node_modules/.store` + symlinks, isolated; global installs force shallow). Peer deps auto-installed since npm 7; conflicts resolved to nearest non-peer spec with a warning, `--strict-peer-deps` makes that an error, `--legacy-peer-deps` ignores peers entirely (npm 3–6 behaviour; must also be passed to `npm ci`). `--omit=dev|optional|peer` (repeatable; default `dev` when `NODE_ENV=production`; omitted deps still resolved into the lock; `omit` incl. dev sets `NODE_ENV=production` for scripts), `--include=prod|dev|optional|peer` wins over omit; deprecated aliases `--production`, `--only`, `--dev`, `--also`, `--optional`.

**Flags**: `--save`(default true; false for `update`), `-P/--save-prod`, `-D/--save-dev`, `-O/--save-optional`, `--save-peer`, `-B/--save-bundle`, `-E/--save-exact`, `--no-save`, `--save-prefix` (`^` default), `--install-links` (pack+copy `file:` deps instead of symlink; no effect on workspaces), `--ignore-scripts`, `--foreground-scripts` (default false; true for pack/publish), `--prefer-offline` / `--offline` / `--prefer-online` (cache modes force-cache / only-if-cached / no-cache), `--package-lock-only`, `--no-package-lock`, `-g/--global` (into `{prefix}/lib/node_modules`, bins to `{prefix}/bin`, Windows `{prefix}/node_modules` + `{prefix}`), `--prefix`/`-C`, `--workspace`/`--workspaces`/`--include-workspace-root`, `--tag` (only affects CLI-specified packages), `--before <date>`, `--min-release-age <days>` (11.10), `--dry-run`, `-f/--force` (refetch; also unlocks many protections), `--cpu/--os/--libc` overrides, `--bin-links`, `--audit`, `--fund`, `--engine-strict`, `--prefer-dedupe`, `--allow-git|--allow-remote|--allow-file|--allow-directory=all|none|root` (default `all` in 11; git/remote → `none` in 12), `--allow-scripts` (one-off/global contexts only), `--strict-allow-scripts`, `--dangerously-allow-all-scripts`, `--json` (11.4). Note: `npm install <name>` with no spec now prefers the newest version whose `engines.node` matches the running Node, even if `latest` doesn't.

**package.json fields** (https://docs.npmjs.com/cli/v11/configuring-npm/package-json): `overrides` (root-only; `"pkg": "spec"`, nested `{"parent": {"child": "spec"}}`, `"."` self key, `"pkg@range"` keys, `$dep` references; specs may be versions/ranges/tags/`npm:`/`file:`/git; overriding a direct dep with a different spec throws EOVERRIDE), `peerDependenciesMeta.<name>.optional`, `bundleDependencies` / `bundledDependencies` (array or boolean), `optionalDependencies` (override `dependencies` entries; install failures tolerated), `os`/`cpu` (allow or `!deny`, from `process.platform/arch`), `libc` (`glibc`/`musl`, only when os=linux), `engines` (advisory warning unless `engine-strict`; `--force` bypasses), `engineStrict` field is ignored (config only), `devEngines` (`runtime`, `packageManager`, `os`, `cpu`, `libc` with `name`/`version`/`onFail: warn|error|ignore`; checked before install/ci/run — npm 10.9+), `bin` (string or map; `#!/usr/bin/env node` required) / `directories.bin` (mutually exclusive with `bin`), `directories.man`, `publishConfig` (any config override at publish time: registry, tag, access, provenance…), `private`, `workspaces` (globs), `files`, `gypfile: false`, `config` (→ `npm_package_config_*`), `funding`, `scripts`, `packageManager` — **not used by npm** (Corepack only; npm reads only `devEngines.packageManager`), `allowScripts` (11.16+: `{"pkg": true, "pkg@1.2.3": true, "pkg": false}`; root/workspace-root only).

**Dependency specifier forms** (npm-package-arg `npa.js`; https://github.com/npm/npm-package-arg): `version`, `range`, `tag` (default `latest`), `alias` (`npm:name@spec`, incl. scoped), `git` (`git://`, `git+ssh://`, `git+http(s)://`, `git+file://`, `ssh://`, SCP-style `git@host:owner/repo`, shorthands `owner/repo`, `github:`, `gist:`, `bitbucket:`, `gitlab:`; `#commit-ish` or `#semver:<range>`; `#pull/273`; submodules cloned), `file` (`file:./x.tgz`, `.tar/.tar.gz/.tgz`), `directory` (`file:../dir`, `./dir`, `~/dir`, `/abs` — symlinked unless `--install-links`; its own deps not installed unless inside project), `remote` (`http(s)://…tgz`). **Not supported** (throw `EUNSUPPORTEDPROTOCOL`): `workspace:` (confirmed: https://github.com/npm/cli/issues/8845, open RFC https://github.com/npm/rfcs/issues/765 — docs briefly and wrongly claimed support; `npm install b -w a` writes a normal range like `^1.0.0` and arborist symlinks the workspace when the range is satisfied), `link:`, `catalog:`, `patch:`. Ranges in a workspace that don't match the local workspace version fall back to the registry.

Git deps that declare `workspaces` or any of `build`, `prepare`, `prepack`, `preinstall`, `install`, `postinstall` are cloned, `npm install`ed in a temp dir (honoring `--ignore-scripts`, `--before`), packed, then installed (pacote/git.js `#prepareDir`). Recognised git env: `GIT_ASKPASS`, `GIT_EXEC_PATH`, `GIT_PROXY_COMMAND`, `GIT_SSH`, `GIT_SSH_COMMAND`, `GIT_SSL_CAINFO`, `GIT_SSL_NO_VERIFY`; `git` config picks the binary.

## 3. Lifecycle scripts (https://docs.npmjs.com/cli/v11/using-npm/scripts; impl: https://github.com/npm/run-script, arborist `reify.js`)

In 11: all run (advisory `allowScripts` warning since 11.16); in 12: blocked unless allowed. |
| `npm rebuild` | `preinstall`, `install`, `postinstall`, `prepare` (prepare only if the folder is a symlink). |
| `npm pack` | `prepack`, `prepare`, `postpack`. |
| `npm publish` | `prepublishOnly`, `prepack`, `prepare`, `postpack`, `publish`, `postpublish` (`prepublish` does NOT run on publish). |

| `npm run <x>` | `pre<x>`, `<x>`, `post<x>` (positional `--` args go only to `<x>`). |

No `uninstall` scripts since npm 7. Since npm 7 install scripts run in the background (output hidden) unless `--foreground-scripts`; `prepare` in workspaces runs concurrently. `--ignore-scripts` skips everything incl. `prepare` (11.0) but `npm run/test/start` still run their target script (just no pre/post). Non-zero exit aborts. Scripts always run with `cwd` = package root.

**Shell**: `/bin/sh` on POSIX, `cmd.exe` (`ComSpec`) on Windows; `script-shell` config (used by run, exec, init). `--if-present` suppresses the missing-script error.

**Environment injected** (`@npmcli/config` `set-envs.js`, `@npmcli/run-script` `make-spawn-args.js`/`package-envs.js`/`set-path.js`, `lib/npm.js`):
- `npm_package_name`, `npm_package_version`, `npm_package_config_*`, `npm_package_engines_*`, `npm_package_bin_*` (objects flattened with `_`, arrays with `_<index>`), `npm_package_json` (abs path). Since npm 7 other package.json fields are **not** exported (RFC 183). Install scripts of deps also get `npm_package_resolved`, `npm_package_integrity`, `npm_package_optional|dev|peer|dev_optional`. Version scripts get `npm_old_version`, `npm_new_version`.
- `npm_lifecycle_event`, `npm_lifecycle_script`, `npm_command` (top-level command name), `npm_execpath` (npm-cli.js), `npm_node_execpath` and `NODE` (node binary), `INIT_CWD`, `HOME`, `EDITOR` (if configured), `NODE_OPTIONS` (from `node-options`), `COLOR` (`1`/`0`), `NODE_ENV=production` when `dev` omitted.

- `PATH` = `[explicit binPaths] + <projectDir>/node_modules/.bin + <each ancestor>/node_modules/.bin … / + <npm>/node_modules/@npmcli/run-script/lib/node-gyp-bin + original PATH` (all case-variants of `Path` merged on Windows).

## 4. `npx` / `npm exec` (https://docs.npmjs.com/cli/v11/commands/npm-exec, https://docs.npmjs.com/cli/v11/commands/npx; impl: `bin/npx-cli.js`, `workspaces/libnpmexec/lib/index.js`, `get-bin-from-manifest.js` in https://github.com/npm/cli)

**Syntax**: `npm exec -- <pkg>[@<ver>] [args]`, `npm exec --package=<pkg> -- <cmd> [args]`, `npm exec -c '<cmd>'`, `npx <pkg>[@ver] [args]`, `npx -p <pkg> <cmd>`, `npx -c '<cmd>'`. `npx` is a shim that rewrites argv to `npm exec`: it translates `-p`→`--package`, `--shell`→`--script-shell`, `--no-install`→`--yes=false`, expands npm shorthands, errors on removed `--always-spawn`, `--ignore-existing`, `--shell-auto-fallback`, `--npm`, `--node-arg`/`-n`, and **inserts `--` before the first positional**, so with `npx` all npm flags must precede the command; with `npm exec` use `--` explicitly. Any npm config (`--registry`, `--prefer-offline`, `--loglevel`, `-w`…) may be given. `-y/--yes`, `-n/--no`, `--call/-c`, `--package` (repeatable), `--script-shell`, `--workspace(s)`, `--include-workspace-root`, `--allow-scripts`, `--strict-allow-scripts`, `--dangerously-allow-all-scripts`.

**Resolution algorithm** (libnpmexec):
1. No args, no `-c`, no `--package` → interactive subshell with npm-run env (refused in CI when stdin is a TTY).
2. If `--package` not given and args exist: (a) if the current project's package.json (or the selected workspace's) has a `bin` named `args[0]`, that local package is installed into the npx cache (auto-yes) so its bin links exist; (b) else if `<project>/node_modules/.bin/<cmd>` exists walking up from the project dir, run it (local bins are always on PATH); (c) else if `<globalBin>/<cmd>` exists, run it; (d) else treat `args[0]` as a package spec.
3. Every requested spec is resolved with `pacote.manifest(spec, {preferOnline: true})` — i.e. `npx foo` always revalidates against the registry unless `--offline`/`--prefer-offline`. A name-only spec matches *any* version in the local tree; a spec with a version/range/tag/url matches only an exact same name+resolved (for ranges, `semver.satisfies` locally; in the npx cache a name-only spec is re-resolved so a newer version gets installed). Directory specs are resolved to absolute paths.
4. Missing packages are installed into **`<npm cache>/_npx/<hash>/`**, hash = first 16 hex chars of sha512 over the sorted package specs joined by `\n` (`npxCache = join(cache, '_npx')`, cache = `~/.npm` / `%LocalAppData%\npm-cache`). The dir gets its own `package.json` with `_npx: { packages: [...] }`, `node_modules`, `node_modules/.bin` (prepended to PATH), and a `concurrency.lock`. Inspect with `npm cache npx ls|info|rm` (11.2).
5. **Prompt rule**: only when something must be installed, and only if `yes` is unset. `--yes` skips; `--no`/`-n`/`--no-install` throws `npx canceled due to missing packages and no YES option`. If stdin is not a TTY **or** `ci-info` detects CI, npm logs a warning (`The following package was not found and will be installed: …`) and proceeds (effectively `--yes`). Interactive prompt: `Need to install the following packages: … Ok to proceed? (y)`.
6. Bin name from manifest (`getBinFromManifest`): if all `bin` entries point to one file → that bin; else if a bin equals the **unscoped** package name → it; else error `could not determine executable to run` (use `--package` + explicit command, e.g. `npx -p typescript tsc`). `npx foo@1.2.3`, `npx github:user/repo`, `npx ./dir`, tarball URLs all work (any npa spec).
7. Execution: `-c` string or args joined, run via `script-shell` with the same env as `npm run` (incl. `npm_config_*`, `npm_lifecycle_event=npx`), cwd = project dir (or each workspace with `--ws`).
- `npm init foo` ⇒ `npm exec create-foo`; `npm init @scope` ⇒ `@scope/create`; `npm init foo@latest` forces registry version over a global `create-foo`.
- Offline: `--offline` errors for anything not in cacache; `--prefer-offline` skips staleness checks.
- Install-script policy for npx (11.16+): only user/global `.npmrc` `allow-scripts` applies (project `allowScripts` ignored); 12 blocks dep install scripts in the npx cache unless allowed.

**Known security concerns**: auto-install on typo was flagged in 2018 (https://github.com/npm/npm/issues/19673) → npm 7 added the prompt, but the prompt is skipped in CI/non-TTY, so `npx <typo>` in pipelines silently installs and runs arbitrary code; postinstall scripts of the fetched package run before the bin does; `-y` in READMEs normalises blind execution; **bin-script confusion** — any dependency can expose `node`/`npm`/`tsc` bins that shadow real ones because local `node_modules/.bin` is always first on PATH for `npx`/scripts, and `--ignore-scripts` doesn't help (https://socket.dev/blog/npm-bin-script-confusion); typosquat campaigns targeting `npx`/`npm install` muscle memory continue (e.g. 10 typosquats of typescript/discord.js/ethers July 2025 https://socket.dev/blog/10-npm-typosquatted-packages-deploy-credential-harvester; 14 OpenSearch typosquats May 2026 https://www.microsoft.com/en-us/security/blog/2026/05/28/typosquatted-npm-packages-used-steal-cloud-ci-cd-secrets/; 37-package campaign Aug 2026 https://openhack.com/blog/37-package-npm-typosquat-windows-stealer). npm's responses: `allowScripts` (RFC 54 https://github.com/npm/rfcs/blob/main/accepted/0054-make-scripts-install-opt-in.md, cites Shai-Hulud Sept 2025 and the Axios hijack Mar 2026), `min-release-age`, `--allow-git/remote`.

## 5. Publishing & auth

**Login** (https://docs.npmjs.com/cli/v11/commands/npm-login; npm-profile): `auth-type=web` default (any `--otp` forces `legacy`). Web: `POST /-/v1/login` → `{loginUrl, doneUrl}`; CLI opens `loginUrl` in the browser and polls `doneUrl` (HTTP 202 + `retry-after` = keep polling; 200 → `{token}`); 4xx/500 → falls back to legacy. Legacy/couch: `PUT /-/user/org.couchdb.user:<name>` body `{_id, name, password, type:"user", roles:[], date}` → `{token}`; on `E409` re-PUT with `_rev`; OTP via `npm-otp` header/prompt. Token stored as `//host/:_authToken` in user `.npmrc` (scoped to `--registry`, optional `--scope=@x` also writes `@x:registry`). Since Dec 2025 `npm login` on npmjs.com yields a **2-hour session token** (not shown in token lists) and 2FA is enforced for publishes within it (https://github.blog/changelog/2025-12-09-npm-classic-tokens-revoked-session-based-auth-and-cli-token-management-now-available/). `npm adduser` = same flow (removed in 12). `npm logout` → `DELETE /-/user/token/<token>` and removes the config. `npm whoami` → `GET /-/whoami`.

**Tokens**: classic tokens — creation disabled 2025-11-05, revoked 2025-11-19/12-09; only **granular access tokens** remain (https://docs.npmjs.com/about-access-tokens). `npm token create` (11.7+) → `POST /-/npm/v1/tokens` with `{name, password, description, packages|packages_all, scopes, orgs, packages_and_scopes_permission: read-only|read-write|no-access (12.1: read-write-stage-only), orgs_permission, expires (days), cidr_whitelist, bypass_2fa}`; flags `--name --token-description --expires --packages --packages-all --scopes --orgs --packages-and-scopes-permission --orgs-permission --cidr --bypass-2fa --password --read-only --otp`. `npm token list` → `GET /-/npm/v1/tokens` (paginated), `npm token revoke <id|token>` → `DELETE /-/npm/v1/tokens/token/<key>`. Write tokens: default 7 days, max 90 days (Oct–Nov 2025). Limits: 1000 tokens/account, 50 orgs, 50 packages+scopes. Bypass-2FA tokens: since Aug 2026 cannot do account/org/package governance; **~Jan 2027 lose direct publish** (stage-only) (https://github.blog/changelog/2026-07-31-restricting-npm-bypass-2fa-granular-access-tokens/).

**2FA**: `npm profile enable-2fa [auth-only|auth-and-writes]`; new TOTP setups disabled since Oct 2025 (WebAuthn/passkeys); new write tokens enforce 2FA by default; new packages default to "require 2FA" (Dec 2025); OTP via `--otp`, `npm-otp` header, or web-OTP flow (401 with `authUrl`/`doneUrl` → browser). `npm access set mfa=none|publish|automation` (package-level) (https://github.blog/changelog/2025-09-29-strengthening-npm-security-important-changes-to-authentication-and-token-management/, https://github.blog/changelog/2025-11-05-npm-security-update-classic-token-creation-disabled-and-granular-token-changes/).

**Publish** (https://docs.npmjs.com/cli/v11/commands/npm-publish; libnpmpublish): `PUT /<escaped-name>` with JSON `{_id, name, description, "dist-tags": {tag: version}, versions: {version: manifest}, access, _attachments: {"<name>-<version>.tgz": {content_type: "application/octet-stream", data: <base64>, length}}}`; manifest `dist` gets `integrity` (sha512 SRI), `shasum` (sha1), `tarball` `<registry>/<name>/-/<basename>-<version>.tgz`; provenance adds `_attachments["<name>-<version>.sigstore"]` (DSSE/sigstore bundle). Fails if name@version exists (ever, even after unpublish). `--tag` (required for prereleases since 11; no implicit `latest` if a higher version exists), `--access public|restricted|private(12)` (scoped packages default restricted on first publish, unscoped always public), `--dry-run`, `--otp`, `--provenance`, `--provenance-file`, `--workspace(s)`, `publishConfig`. Files: `files` allowlist, `.npmignore`/`.gitignore`, always-included `package.json`/README/LICENSE/main/bin, never-included `.git`, `.npmrc`, `node_modules` (except bundled), `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `bun.lockb`; `npm-shrinkwrap.json` is published. Symlinks never packed. `npm pack`: `--pack-destination`, `--dry-run`, `--json`, `--ignore-scripts`; writes `<name>-<version>.tgz` (scope `@` dropped, `/`→`-`).

**Trusted publishing / provenance** (https://docs.npmjs.com/trusted-publishers, https://docs.npmjs.com/generating-provenance-statements, https://github.blog/changelog/2025-07-31-npm-trusted-publishing-with-oidc-is-generally-available/): GA 2025-07-31; needs npm ≥11.5.1, Node ≥22.14. Providers: GitHub Actions (hosted runners; needs `permissions: id-token: write`), GitLab CI (`id_tokens: NPM_ID_TOKEN: aud: "npm:registry.npmjs.org"` + `SIGSTORE_ID_TOKEN: aud: sigstore`), CircleCI (11.11; `NPM_ID_TOKEN` env; no provenance). CLI flow (`lib/utils/oidc.js`): in CI, read `NPM_ID_TOKEN` or mint via `ACTIONS_ID_TOKEN_REQUEST_URL` with audience `npm:<registry host>`, then `POST /-/npm/v1/oidc/token/exchange/package/<name>` → short-lived publish token; **provenance auto-enabled** when OIDC succeeds and repo is public (GitLab needs `SIGSTORE_ID_TOKEN`) unless `provenance=false`/`NPM_CONFIG_PROVENANCE=false`/`publishConfig.provenance=false`. Without OIDC: `npm publish --provenance` (npm ≥9.5) requires a public `repository` matching the build; sigstore Fulcio/Rekor; verify with `npm audit signatures`. Up to 10 trusted publishers per package; configs created after 2026-09-03 default to stage-only. `npm trust github|gitlab|circleci [pkg] --file … --repo/--project … --env … --allow-publish --allow-stage-publish -y`, `npm trust list`, `npm trust revoke --id`. **Staged publishing** `npm stage publish` → `POST /-/stage/package/<name>` (`{stageId}`), `npm stage list|view|download|approve (2FA)|reject (2FA)`; tag immutable per stage; version index shared with real publishes.

**Other registry ops**: `npm version` (see §3; `--allow-same-version`, `--no-git-tag-version`, `--no-commit-hooks`, `--preid`, `-m`, `from-git`, `--sign-git-tag`, `--sign-git-commit`, `--tag-version-prefix`, workspaces + `--workspaces-update`). `npm dist-tag ls` → `GET /-/package/<name>/dist-tags`; `add` → `PUT /-/package/<name>/dist-tags/<tag>` (body = version JSON string); `rm` → `DELETE …/<tag>`; tags that parse as semver ranges rejected; `latest` is the only special tag. `npm deprecate <spec> "<msg>"` / `undeprecate`: GET full packument, set `versions[v].deprecated` for all matching versions (ranges include prereleases), `PUT /<name>` (empty message un-deprecates; `--dry-run`). `npm access list packages [user|scope|scope:team]` (`/-/user|org|team/…/package`), `list collaborators` (`/-/package/<n>/collaborators`), `get status` (`/-/package/<n>/visibility`), `set status=public|private`, `set mfa=none|publish|automation` (`POST /-/package/<n>/access`), `grant read-only|read-write <scope:team>` / `revoke` (`PUT|DELETE /-/team/<scope>/<team>/package`). `npm owner add|rm|ls` edits `maintainers` on the packument (`PUT /<name>/-rev/<rev>`; user lookup `GET /-/user/org.couchdb.user:<user>`). `npm unpublish <name>@<ver>` (PUT packument without the version, then `DELETE /<name>/-/<tarball>/-rev/<rev>`) or `npm unpublish <name> --force` (`DELETE /<name>/-rev/<rev>`); registry policy (https://docs.npmjs.com/policies/unpublish): any version within 72h if no dependents; later only if no dependents, <300 weekly downloads, single owner; whole-package unpublish blocks republish for 24h; name@version never reusable. `npm team`/`npm org` → `/-/org/<scope>/team`, `/-/team/<scope>/<team>[/user]`, `/-/org/<org>/user`.

## 7. Audit, outdated, update, dedupe, prune, ls/explain, query, sbom, doctor, cache

- **`npm audit`** (https://docs.npmjs.com/cli/v11/commands/npm-audit; arborist `audit-report.js`): requires a lockfile (`--no-package-lock` to build the tree ad hoc); `POST /-/npm/v1/security/advisories/bulk` to the configured registry (gzip JSON body `{ "<name>": ["1.0.0","1.2.0"] }`, omitting `--omit` types, links, and version-less nodes); response `{ "<name>": [ {id, url, title, severity, vulnerable_versions, cwe, cvss, …} ] }`; metavulns computed with `@npmcli/metavuln-calculator` (cached in `~/.npm/_cacache`); output `auditReportVersion: 2` JSON. **No quick-audit fallback since 11.0** (the doc page is stale). Exit non-zero if any vuln ≥ `--audit-level` (`info|low|moderate|high|critical|none`). `npm audit fix [--force] [--dry-run] [--package-lock-only] [--omit=dev]` = a full install; warns and exits non-zero if `before`/`min-release-age` blocks a fix. Audit runs implicitly on install (`audit=false` disables). `npm audit signatures [--json --include-attestations]`: loads registry keys from the Sigstore TUF root (target `<host>/keys.json`) falling back to `GET /-/npm/v1/keys` (`{keys:[{expires, keyid:"SHA256:…", keytype:"ecdsa-sha2-nistp256", scheme, key}]}`); verifies `dist.signatures[{keyid,sig}]` over `${name}@${version}:${dist.integrity}`; fetches attestations from `dist.attestations.url` (path `/-/npm/v1/attestations/<name>@<version>`, re-rooted to the configured registry) → `{attestations:[{predicateType, bundle}]}` verified with sigstore (keyless Fulcio or registry keys); not supported for global packages.
- **`npm outdated [pkg…]`** (`--all`, `--long`, `--json`, `--parseable`, `-g`, `--before`): columns Current / Wanted (max satisfying range) / Latest (`latest` tag) / Location / Depended by; red = in-range update, yellow = out-of-range; git deps always "git"; linked deps "linked".
- **`npm update [pkg…]`**: highest version satisfying all ranges in the tree (prefers a single version over duplicates), installs missing, `--save` to rewrite ranges, `-g` updates globals to `latest` (may downgrade).
- **`npm dedupe`** / **`npm find-dupes`** (dry-run): re-hoists, never installs new modules, never edits package.json ranges; `--prefer-dedupe` at install time.
- **`npm prune [pkg…]`** (`--omit=dev`/`NODE_ENV=production` removes devDeps, `--dry-run`, `--json`).
- **`npm ls [spec…]`** (`ll`/`la` long): logical tree, flags extraneous/missing/invalid, git URLs in parentheses; `--all`, `--depth`, `--json`, `--parseable`, `--link`, `--omit/--include`, `--package-lock-only`, `-g`. **`npm explain|why <spec|path>`** prints reverse chains.
- **`npm query '<selector>'`** (https://docs.npmjs.com/cli/v11/using-npm/dependency-selectors): combinators `>`, descendant (space), `~`; `*`, `#name`, `#name@range`, `,`, `.prod .dev .optional .peer .workspace .bundled`; pseudo `:root :scope :empty :private :link :deduped :overridden :extraneous :invalid :missing :not() :has() :is() :semver(spec[,selector[,fn]]) :path(glob) :type(git|registry|tag|version|range|alias|file|directory|remote) :outdated(any|in-range|out-of-range|major|minor|patch) :vuln([severity=high],[cwe=…]) :attr(path…, [attr op value])`; attribute ops `= ~= *= |= ^= $=`; returns JSON array of package manifests with `queryContext`; `--expect-results`, `--expect-result-count`, `--package-lock-only`, `-g`.
- **`npm sbom --sbom-format=spdx|cyclonedx [--sbom-type=library|application|framework] [--omit] [--package-lock-only]`** (purl `pkg:npm/…`, SHA-512 hashes; 12 changes CycloneDX naming).
- **`npm doctor [connection] [registry] [versions] [environment] [permissions] [cache]`**: `GET /-/ping`, npm/node version vs latest, registry non-default, git on PATH, cache/global-bin/node_modules permissions, cache tarball checksums.
- **`npm cache add <spec> | clean --force | ls [name@ver] | verify | npx ls|rm|info`**: content-addressable cacache under `<cache>/_cacache`; never trusts corrupt data; `_logs`, `_npx`, `_update-notifier-last-checked`, `_cacache/tmp` siblings.

## 8. Registry HTTP protocol essentials (https://github.com/npm/registry/blob/main/docs/REGISTRY-API.md, https://github.com/npm/registry/blob/main/docs/responses/package-metadata.md, https://docs.npmjs.com/cli/v11/using-npm/registry; impl: https://github.com/npm/pacote `lib/registry.js`, https://github.com/npm/npm-registry-fetch)

- **Packument** `GET /<name>` (scoped: `/@scope%2Fname`). Accept `application/vnd.npm.install-v1+json; q=1.0, application/json; q=0.8, */*` → abbreviated "corgi" doc `{name, modified, dist-tags, versions:{v:{name, version, dist, dependencies, optionalDependencies, devDependencies, peerDependencies, peerDependenciesMeta, bundleDependencies, bin, directories, engines, os, cpu, libc, funding, deprecated, hasInstallScript, _hasShrinkwrap, acceptDependencies}}}`; full doc (`application/json`) adds `_id`, `_rev`, `time` (per-version publish timestamps + created/modified — required for `--before`/`min-release-age`, so pacote switches to full metadata then), `users`, `readme`, `maintainers`, `author`, `repository`, `license`, `keywords`, and per-version `_npmUser`, `_npmVersion`, `_nodeVersion`, `main`, `scripts`, etc. A corgi 404 makes pacote retry with full metadata. `GET /<name>/<version|tag>` returns one manifest.
- **`dist`**: `tarball` (`<registry>/<name>/-/<basename>-<version>.tgz`), `shasum` (sha1), `integrity` (sha512 SRI; preferred, mismatch = EINTEGRITY), `fileCount`, `unpackedSize`, `signatures: [{keyid, sig}]` (ECDSA P-256 over `name@version:integrity`), `attestations: {url, provenance: {predicateType}}`, legacy `npm-signature` (PGP, retired). Lockfile `resolved` is replaced per `replace-registry-host`.
- **Caching**: make-fetch-happen + cacache; HTTP cache semantics with ETag/`If-None-Match` and `Last-Modified`/`If-Modified-Since` revalidation; modes `default` / `no-cache` (prefer-online) / `force-cache` (prefer-offline) / `only-if-cached` (offline); packuments never integrity-checked, tarballs always. Retries on idempotent reads for network errors/5xx (`fetch-retries*`), `fetch-timeout`.
- **Request headers**: `user-agent`, `npm-auth-type`, `npm-scope` (project scope), `npm-command`, `npm-session` (if set), `authorization: Bearer <token>` or `Basic <base64>`, `npm-otp`, `content-type: application/json` / `application/octet-stream`, `content-encoding: gzip` (bulk advisories). Response header `npm-notice` is logged. Auth is chosen by longest matching nerf-dart; tarballs on a different host than the registry get no credentials.
- **Write/auth endpoints**: `PUT /<name>` (publish, deprecate, owner), `PUT|DELETE /<name>/-rev/<rev>`, `DELETE /<name>/-/<file>/-rev/<rev>`, `POST /-/stage/package/<name>`, `GET|PUT|DELETE /-/package/<name>/dist-tags[/<tag>]`, `GET /-/package/<name>/collaborators|visibility`, `POST /-/package/<name>/access`, `PUT|DELETE /-/team/<scope>/<team>/package`, `GET /-/{user,org,team}/…/package`, `/-/org/<org>/user`, `/-/org/<scope>/team`, `/-/team/<scope>/<team>[/user]`, `POST /-/v1/login` + `doneUrl` polling, `PUT /-/user/org.couchdb.user:<name>`, `DELETE /-/user/token/<token>`, `GET /-/whoami`, `GET /-/ping`, `GET|POST /-/npm/v1/user`, `GET|POST /-/npm/v1/tokens`, `DELETE /-/npm/v1/tokens/token/<id>`, `POST /-/npm/v1/oidc/token/exchange/package/<name>`, `GET /-/npm/v1/keys`, `GET /-/npm/v1/attestations/<name>@<version>`, `POST /-/npm/v1/security/advisories/bulk`, `GET /-/v1/search?text&size(≤250)&from&quality&popularity&maintenance` (qualifiers `author:`, `maintainer:`, `scope:`, `keywords:`, `is:/not:unstable|insecure`, `boost-exact:false`). Download counts live on `api.npmjs.org/downloads/…` (not used by the CLI).

## 9. Node.js integration points

- **Corepack / `packageManager`** (https://nodejs.org/docs/latest-v24.x/api/corepack.html, https://github.com/nodejs/corepack/blob/main/README.md, https://github.com/nodejs/node/pull/59835): experimental; bundled from Node 14.19/16.9 **through Node 24.x** (24 EOL 2028-04-30, must still be enabled with `corepack enable`); **removed from Node 25.0.0 and later** (TSC vote 2025-03-19; `build: remove corepack from release tarballs` merged 2025-09-12); userland install `npm i -g corepack`. `"packageManager": "<npm|yarn|pnpm>@x.y.z[+sha224.<hash>]"` (exact version required; also URL form `name@https://…tgz#sha224.…`); `devEngines.packageManager {name, version, onFail}` honoured by both Corepack and npm (npm ignores top-level `packageManager`). Env knobs `COREPACK_ENABLE_STRICT`, `COREPACK_ENABLE_PROJECT_SPEC`, `COREPACK_ENABLE_AUTO_PIN`.
- **`node --run <script>`** (https://nodejs.org/api/cli.html#--run): added v22.3.0/v20.18.0, stable since v24.10.0/v22.21.0; runs `scripts.<name>` from the **current directory's** package.json only (no parent search), via `sh`/`cmd.exe`, inherits env (incl. `--env-file`), sets `NODE_RUN_SCRIPT_NAME` and `NODE_RUN_PACKAGE_JSON_PATH`; lists scripts when no name given; no `pre`/`post` hooks and no `npm_*` variables (it does prepend `node_modules/.bin` to PATH).
- **Bin shims** (https://github.com/npm/bin-links, https://github.com/npm/cmd-shim): local bins → `node_modules/.bin/<name>`, global → `{prefix}/bin` (POSIX) or `{prefix}` (Windows); POSIX = symlink (link-gently: refuses to clobber a foreign file/symlink → EEXIST unless `--force`, fixes exec bits); Windows = `cmd-shim` writes three files per bin — `<name>` (`#!/bin/sh` script for Git Bash/Cygwin/MSYS), `<name>.cmd`, `<name>.ps1` (`#!/usr/bin/env pwsh`) — parsing the target's shebang (`#!/usr/bin/env node`, `-S`, env vars) to choose the interpreter; `--no-bin-links` disables; `npm rebuild` relinks.
